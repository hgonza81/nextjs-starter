# Review by architect — 002-platform-hardening — round 1 (requirements + flows; no wireframes in this epic)

Verified against `node_modules/next/dist/docs/` (Next.js 16.4.6): `01-app/03-api-reference/03-file-conventions/instrumentation.md`, `error.md`, `proxy.md`, `01-app/02-guides/open-telemetry.md`, `content-security-policy.md`, `05-config/01-next-config-js/serverActions.md`, `poweredByHeader.md`, `04-functions/unstable_rethrow.md`.

## Summary
The epic is sound and proportionate. All technical decisions can be taken by the architect without the Product Owner; Q3 (hard delete, only `created_at`/`updated_at`) is confirmed and I add no product-level question. The biggest issues are three gaps in `flows.md`: the reference code cannot always be the framework digest and cannot be put in a route handler response (Q6, PH-AC-10), `onRequestError` must not log the request path (PII), and a nonce CSP forces dynamic rendering and needs a `proxy.ts`.

Top quality attributes for this epic: (1) safety of what leaves the server (no PII in logs, pages, headers); (2) consistency for later modules (one error shape, one wrapper, one convention set, enforced not documented); (3) zero cost when unused (no telemetry destination = no overhead, no failure). Not optimizing: production-grade observability, throughput, caching.

## Concerns and gaps
- [important] **Reference code vs digest (Q6, BR-02, PH-FL-04).** `error.digest` exists for errors forwarded from Server Components (error.md), and `onRequestError` receives it when React processed the error. It is a hash of the error, so the same bug gives the same code on every occurrence (fine for lookup, not unique per request). It is absent for errors thrown in Client Components and not guaranteed for route handlers or actions. Q6 default A (omit the line when absent) is acceptable for the page; for actions the wrapper generates its own code (see proposals). BR-02 wording ("non-guessable-free of personal data") is garbled: it should read "contains no personal data; it needs not be secret".
- [important] **PH-AC-10 / PH-FL-04 step 3 not achievable as written.** `onRequestError` is observe-only (returns `void`); it cannot change a route handler's response, so "response is a generic error body with the code" cannot come from the hook. Next returns its own generic 500. Fix: for route handlers require only "generic response, no internals, one log entry"; the code in the body is delivered by the action wrapper only. Unwrapped actions that throw show Next's generic error with no code.
- [important] **BR-04 and the hook.** `onRequestError`'s `request.path` includes the query string (may carry tokens or emails in epic 003) and `request.headers` carries cookies and authorization. The hook must log only `context.routePath`, `context.routeType`, `request.method`, error class name, `digest`, and the DB error `code` when present, never `path`, headers or `err.message` (PH-AC-11 already implies the message). Add an explicit AC: "path with `?token=x` and `Authorization` header never appear in the log entry".
- [important] **The wrapper must not swallow framework control flow.** `redirect()`, `notFound()`, `forbidden()` and dynamic-rendering signals are thrown errors. A wrapper that catches everything and returns `unexpected` breaks them. The wrapper must call `unstable_rethrow(err)` (exists in this version) first in its catch. Add an AC (redirect inside a wrapped action still redirects).
- [important] **Nonce CSP implies `proxy.ts` and fully dynamic rendering** (content-security-policy.md): static pages get no nonce, so inline Next bootstrap scripts are blocked; PPR is incompatible. Flows say "any page" carries a strict CSP (PH-FL-09, PH-AC-27) without noting this. Consequences: a `src/proxy.ts` is created in this epic (epic 003 will add Supabase session refresh to the same file), the root layout must opt in to dynamic rendering, and the static 404, error and global-error pages must be proven under the CSP by E2E (global-error renders its own document: confirm it receives the nonce; if not it needs a hash or stays script-free).
- [important] **CSP `connect-src` for Supabase.** Epic 003 calls Supabase Auth from the browser; the policy must include the origin of `NEXT_PUBLIC_SUPABASE_URL` (from `publicEnv`) in `connect-src`, or auth will break silently under the CSP. Add to PH-FL-09 alt flows.
- [important] **"Agreed structure" for `gen:module` conflicts with C1 and the epic 001 rule** "no empty folders, no placeholder `index.ts`" (docs/architecture.md, Module folders). Resolve explicitly: the generator creates only `index.ts` (public API with a header comment listing the allowed subfolders); subfolders are created when they have content (C1). Say so in the spec.
- [important] **Testing faults.** PH-AC-01/06/08-10 need a route that throws. It must never ship active. Put the fault pages and routes under `/design/errors/*`, reusing `DESIGN_PAGE_ENABLED` (404 in production, existing E2E gate). Headers, CSP, digest and "no secret in HTML" tests must run against `next build && next start` (the Playwright webServer already does).
- [minor] **PH-AC-19** ("no ad hoc `console.error` remains") should be an ESLint `no-console` rule with the logger file as the only exemption, not a grep (a rule nobody checks is broken).
- [minor] **PH-AC-08 "exactly one log entry"**: dev mode may log twice (React and `onRequestError`). Assert on the production build.
- [minor] **PH-FL-07 invalid variable "same behavior as ADR 0004"**: the OTel SDK reads `OTEL_*` itself from `process.env`; our `env.server.ts` must validate the ones we document (endpoint URL, protocol, service name) so a typo fails at startup. C11 is respected because the SDK, not our code, reads the rest.
- [minor] **Request id (PH-HR-04)** is not defined: nobody generates one. See logger proposal (read it from the incoming header, never generate).
- [minor] **docs/architecture.md C8** says "No observability tooling in the MVP": amend in this epic (ADR supersedes that sentence). C6 gets the concrete result type.
- [minor] **PH-AC-48 / Q8**: if Q8 default A is taken, delete PH-AC-48 (as flows already note).

## Proposals (concrete answers, no questions needed)

### Database conventions (ADR) — PH-HR-08
- **Id:** `id uuid primary key default gen_random_uuid()` (v4, built in, no extension). Matches `auth.users.id`, not enumerable. UUIDv7 would need PG18 (`uuidv7()`) and local Postgres is 17; switching later is a default-value change only, so this is cheap to revisit. Rejected: bigint identity (enumeration, mismatch with auth ids), ULID/text (extra type, no gain).
- **Naming:** `snake_case`; tables plural (`tenants`, `memberships`); columns singular; FK columns `<singular>_id` (`tenant_id`); constraints and indexes `<table>_<cols>_{pkey,key,fkey,idx}` (Postgres defaults); RLS policies are sentences naming action and actor (`members can read their tenant`); functions `snake_case` verbs; migration files `YYYYMMDDHHMMSS_description.sql` (existing).
- **Timestamps:** `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()`. Never `timestamp` without zone.
- **Trigger:** one migration creates `public.set_updated_at()` (`language plpgsql`, `set search_path = ''`, SECURITY INVOKER, sets `new.updated_at = now()`); each table adds `create trigger <table>_set_updated_at before update on ... for each row execute function public.set_updated_at()`. No EXECUTE grant needed to fire a trigger, so the 0003 default-privilege revoke does not interfere (assert in the test).
- **Delete:** hard delete everywhere; `ON DELETE` is chosen deliberately per FK (child rows of a tenant `CASCADE`, otherwise `RESTRICT`), stated in the migration.
- **Audit:** only `created_at` and `updated_at`. Seam: nullable `deleted_at`, `created_by`, `updated_by` can be added to one table later without a rewrite. Security-event audit (logins, role changes) is a future module, not column conventions.
- **Enforcement:** extend `tests/db/schema-guard.test.ts` (it already queries the catalog) with per-table rules for every `public` table: (1) `id uuid` primary key; (2) `created_at` and `updated_at` `timestamptz not null default now()`; (3) a `BEFORE UPDATE` trigger calling `set_updated_at`; (4) snake_case identifiers; (5) every FK column is the leading column of an index. Exceptions only through a named allowlist with a reason string, failing with "table X violates rule Y". The `tenant_id` rule belongs to epic 003 (seam: add it there).

### OpenTelemetry (ADR) — PH-HR-05/06
- **Package choice: manual `@opentelemetry/sdk-node` with OTLP/HTTP exporters** (`exporter-trace-otlp-http`, `exporter-logs-otlp-http`, `exporter-metrics-otlp-http`, plus `sdk-logs`, `sdk-metrics`, `api`, `api-logs`, all exact-pinned per ADR 0010), started from `src/instrumentation.node.ts`, imported by `register()` only when `NEXT_RUNTIME === "nodejs"` (this repo has no edge code; the docs say NodeSDK is incompatible with edge). Reason: vendor-neutral, configured by the standard `OTEL_*` variables, nothing Vercel-specific. Rejected: `@vercel/otel` (also valid and shorter; couples to Vercel conventions we do not need and still requires the same peer packages; swapping is a one-file change either way, so this is a low-regret door). Rejected: gRPC exporters (native/size cost, Vercel serverless).
- **Behavior without a destination:** `register()` starts the SDK only if `OTEL_EXPORTER_OTLP_ENDPOINT` or a per-signal endpoint is set. Otherwise nothing starts, `@opentelemetry/api` calls are no-ops, zero overhead, no connection-refused noise (NodeSDK's default endpoint is localhost:4318, which would spam errors if started unconditionally). This satisfies BR-09.
- **Never blocking (BR-10):** batch processors only (never `SimpleSpanProcessor`); exporter errors go to the OTel diagnostic logger, not the request.
- **Metrics:** the pipeline is wired (requirement says metrics) with no custom metrics defined; Next emits spans only. Do not add runtime-metrics instrumentation.
- **Variables validated in `env.server.ts`:** `OTEL_EXPORTER_OTLP_ENDPOINT` (optional URL), `OTEL_EXPORTER_OTLP_PROTOCOL` (optional, only `http/protobuf` or `http/json`), `OTEL_SERVICE_NAME` (optional, default `nextjs-starter`). `OTEL_EXPORTER_OTLP_HEADERS` carries credentials in cloud: consumed by the SDK only, never logged, added to `.env.example` as a commented line with a warning.
- **Risk to verify in the first task:** bundling of `sdk-node` under Turbopack (may need `serverExternalPackages`); and that a throwaway OTLP receiver in `test` gets a trace (PH-AC-21).

### Local collector — PH-HR-06 / Q1
- **Grafana LGTM, single container** (`grafana/otel-lgtm`: Grafana, Tempo, Loki, Prometheus, OTLP receiver 4318). Jaeger rejected (traces only). With no collector: nothing runs and the app logs JSON to stdout (BR-09).
- `docker/observability/compose.yaml`, ports bound to `127.0.0.1` (Grafana 3000, OTLP 4317/4318), image pinned to an exact tag at implementation time (ADR 0010 spirit), no volume (ephemeral by default). Scripts `pnpm obs:start` / `pnpm obs:stop` (`docker compose -f ... up -d` / `down`). Documented variables: `OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318`, `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf`. Not wired into `pnpm dev`, tests or CI (BR-11). Verification is a documented manual check (PH-AC-24/26).

### CSP and headers (ADR) — PH-HR-07 / Q2
- **Policy:** Q2 option A with one pragmatic relaxation. `script-src 'self' 'nonce-<n>' 'strict-dynamic'` (plus `'unsafe-eval'` in development only); this is where XSS protection lives. `style-src 'self' 'unsafe-inline'`: Radix/shadcn render inline `style` attributes in SSR HTML (nonces do not apply to style attributes) and Sonner injects a `<style>` element at runtime; nonce-only styles are fragile for little security gain. Plus `default-src 'self'`, `img-src 'self' blob: data:`, `font-src 'self'` (Geist is self-hosted), `connect-src 'self' <supabase origin>` (+ `ws:` in dev for HMR), `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`, `upgrade-insecure-requests` (production only).
- **Mechanism:** `src/proxy.ts` (Next 16 name for middleware) generates the nonce and sets CSP on request and response, with the matcher from the docs (skip `_next/static`, images, prefetches). The policy string is built by a pure function in `src/lib` (unit-tested; the Supabase origin comes from `publicEnv`). The root layout calls `await connection()` so every page is dynamic. All other headers are static in `next.config.ts` `headers()`: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `X-Frame-Options: DENY` (legacy, next to `frame-ancestors`), and in production `Strict-Transport-Security: max-age=63072000; includeSubDomains` (no `preload`: irreversible-ish and not needed).
- **Hardening:** `poweredByHeader: false`; no CORS headers are ever set (closed by default means: do nothing, and a test asserts it); `experimental.serverActions.bodySizeLimit: '1mb'` stated explicitly (it is the default; documents the limit) and `allowedOrigins` left unset (Next already compares `Origin` with `Host`). Note for the docs: the limit covers Server Actions only; route handlers that read bodies must enforce their own cap.
- **Fallback rule (already in Q2):** if E2E shows the nonce approach breaks a page (error pages, global-error), relax the minimum and record it. Fallback B is a static `unsafe-inline` CSP in `next.config.ts` (docs "Without Nonces"). Rejected: experimental SRI (experimental, may change).

### Error and result types (ADR) — PH-HR-03
- `src/lib/errors.ts` (domain-free, no `server-only` so the UI can import the types): `AppErrorType = "validation" | "not_found" | "forbidden" | "conflict" | "unexpected"`; `class AppError extends Error { type; fieldErrors?: Record<string, string[]>; }` with helpers `validationError(fieldErrors)`, `notFound()`, `forbidden()`, `conflict(msg)`. Safe messages are fixed strings per type unless the developer passes one.
- Wire shape (plain, serializable, no class across the server action boundary): `type ActionError = { type: AppErrorType; message: string; fieldErrors?: Record<string, string[]>; ref?: string }` and `type Result<T> = { ok: true; data: T } | { ok: false; error: ActionError }`. `ref` is present only for `unexpected`.
- **DB mapping `fromDbError(err)`, duck-typed on `.code` (so `lib` imports nothing from `db`), walking `cause` up to 3 levels (Drizzle wraps driver errors; verify against the real DB in `test:db`):** `23505` unique violation to conflict; `23503` foreign key to conflict; `42501` (includes "violates row-level security policy" on INSERT/UPDATE) to forbidden; `23502`/`23514` not-null/check to validation with no field mapping; anything else (including `57014` timeout, `40001`, `40P01`) to unexpected with no DB message. Note: RLS on SELECT/UPDATE/DELETE filters silently (zero rows), which is why "not found when no row" is the handler's job, as BR-08 already says; forbidden vs not found must not leak existence across tenants (return `not_found` for rows hidden by RLS).
- **Reference code:** `ref = error.digest ?? newRef()`, `newRef()` = 8 hex chars from `crypto.randomUUID()`. No PII, not secret.

### Action wrapper — PH-HR-10
```ts
// src/lib/action.ts
export function defineAction<S extends z.ZodType, T>(opts: {
  name: string;               // log event name, e.g. "tenants.create"
  schema: S;
  handler: (input: z.output<S>) => Promise<T>;
}): (input: unknown) => Promise<Result<T>>;
```
Order (BR-15): `schema.safeParse` (invalid: return validation via `z.flattenError`, handler not run) then handler then catch: `unstable_rethrow(err)` first, then `AppError` to result (log `warn`), then `fromDbError`, then unknown to `unexpected` + `ref` + `logger.error`. No auth inside yet (spec has none). Seam for epic 003: a second optional `ctx` argument or a sibling `defineAuthedAction` that resolves the verified context via `getUser()` before the handler; do not build it now. To verify in the first task: a `"use server"` file exporting `defineAction(...)` results is accepted by the Next build (it checks exports are async functions).

### Logger — PH-HR-04
- `src/lib/logger.ts`, `import "server-only"`. API: `logger.debug|info|warn|error(event, fields?)` and `logger.exception(event, err, fields?)`. `fields` type is `Record<string, string | number | boolean | null>` (no objects, no `Error`, enforced by TypeScript), strings truncated to 200 chars, and a runtime key denylist (`/email|token|password|secret|authorization|cookie|body|dsn|url|key/i`) whose values are replaced by `"[redacted]"`. `exception` extracts only `error_name`, `error_code` (DB or `AppError` code) and `digest`, never `message`/`stack`.
- Output: one line `{ts, level, event, trace_id?, span_id?, request_id?, ...fields}` via `process.stdout.write`. `trace_id`/`span_id` come from `trace.getActiveSpan()` (`@opentelemetry/api`, no-op without the SDK, so absent when telemetry is off). `request_id` is read by the caller from an incoming `x-request-id` or `x-vercel-id` header when it has one (the hook does; nothing is generated). Each call also emits an OTel `LogRecord` through `@opentelemetry/api-logs` (no-op without the SDK) so Grafana receives logs with trace correlation. No log level env variable (YAGNI). No pino/winston: one 40-line module.
- ESLint `no-console` for `src/**` with the logger file exempt (PH-AC-19). `src/app/api/health/db/route.ts` moves to `logger.exception`.

### Pagination — PH-HR-09 / Q5 (ADR, short)
- Offset, with total count. Two halves because `lib` cannot import `db`: **`src/lib/list-params.ts`** (pure): `listParams({ sortable: [...], filters: { name: "contains", status: "eq" }, defaultSort, defaultPageSize: 20, maxPageSize: 100 })` returns a Zod schema that parses `searchParams` into `{ page, pageSize, sort: { field, dir }, filters }` (page >= 1, unknown keys rejected, invalid input becomes a `validation` AppError). **`src/db/paginate.ts`** exported from `@/db`: `paginate(tx, { table, columns, params, where? })` returning `{ rows, total, page, pageSize, pageCount }`. It uses Drizzle parameterized predicates only; `contains` escapes `%`, `_` and `\`; ORDER BY always appends `id` as tiebreaker (stable order, PH-AC-38); count is a second query on the same `tx`, so RLS applies (PH-AC-42); a page past the end returns `rows: []` with the real total. Keyset is a future per-list sibling (`cursor` variant); no schema change needed.

### `gen:module` — PH-HR-11 / Q7
- `scripts/gen-module.mts` run as `node scripts/gen-module.mts <name>` (same pattern as `db-schema.mts`; script `pnpm gen:module`). Name must match `^[a-z][a-z0-9]*(-[a-z0-9]+)*$` (rejects empty, uppercase, spaces, path characters, so no path traversal). Creates `src/modules/<name>/index.ts` with `export {};` and a header comment (public API only; add `actions/ queries/ schemas/ components/ types.ts` when they have content). Uses exclusive create (`mkdir` non-recursive, `writeFile` with `wx`) so it never overwrites. Existing boundary lint rules are glob-based on `src/modules/*`, so they apply with no change. Test: run the script against a temp base directory (optional `--dir`), then assert lint and the deep-import fixture. No placeholder tests (Q7 A). This is a two-way door: no ADR, a section in `docs/architecture.md`.

## Risks and assumptions
- Nonce CSP changes rendering for the whole app (all dynamic). Acceptable: the app is authenticated and mostly dynamic from epic 003. Mitigation: fallback B documented.
- Global-error may not receive the nonce; E2E (PH-AC-31 extended to the error pages) decides.
- `onRequestError` not firing for `redirect()` and `notFound()` is assumed; the test must assert it (no log entry for them).
- OTel packages are new releases subject to the 24h `minimumReleaseAge` gate; they add about 9 direct dependencies (justified by PH-HR-05; acceptable, all exact-pinned).
- Turbopack bundling of `sdk-node` and Drizzle error wrapping shape (`cause`) are unverified assumptions: both are first-task spikes with a test.
- Assumes no edge runtime code (proxy runs on Node by default in this Next version; verify at implementation).
- Seams for out-of-scope items: rate limiting (epic 003) goes in `proxy.ts` or the wrapper; Sentry or Grafana Cloud is `OTEL_*` variables only (plus headers); keyset pagination, `deleted_at`, `created_by`, `tenant_id` guard rule, authed action wrapper are each additive.
