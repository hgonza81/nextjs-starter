# Review by tester — 002-platform-hardening — round 2 (final consistency read of spec.md, ADRs 0012-0016, questions.md)

## Summary
Round 1 blockers are resolved: seams (D14, PH-FR-23), relaxed PH-AC-10, wrapped vs unwrapped logging (PH-AC-64), measurable PH-AC-22/23/30/39/40, trigger clock (PH-AC-69), request id (PH-AC-70). Every PH-AC is testable, and nothing needs the collector or any Docker beyond the Supabase stack CI already starts for `test:db` (E2E stays DB-free, receiver is a plain Node server, in-memory exporter is unit-only). Five gaps remain; one is a real contradiction (G1) that would make PH-AC-08 flaky.

## Concerns and gaps

- [important] **G1. PH-AC-08 "unique code per test" contradicts D5.** The digest is a hash of the error, so the same fixture error yields the same `ref` in every test and every CI retry; "exactly one entry" would count entries from earlier tests/attempts in the same tee'd file. The wrapper `ref` is random, but pages and the hook use the digest.
- [important] **G2. "Throwing root-layout case" (PH-FR-23, PH-AC-03, 61) has no mechanism.** A fault route under `/design/errors/*` cannot make the root layout throw (a nested layout error goes to `error.tsx`, not `global-error`). Something in the root layout, `proxy.ts` or the config must be fault-injectable, and that is production code in the artifact. Undecided; PH-AC-03/61 depend on it.
- [important] **G3. D14 is not implementable as written for the E2E harness.** Missing: how stdout is tee'd portably and with the right exit code (a `| tee` pipe hides the exit status), file location (git-ignored), truncation per server start, and how tests find the file. Missing also: which extra servers exist (telemetry-on, closed-port, bad-variable spawn), their ports, and that the receiver must listen before the telemetry-on server starts (Playwright `webServer` cannot allocate free ports dynamically; use fixed ports derived from `E2E_PORT`). Batch delays for logs and traces must both be shortened.
- [important] **G4. No level is named per PH-AC for the new/changed criteria.** The section 16 table names levels per HR only. The ones that are ambiguous: PH-AC-58 (E2E vs hook unit), PH-AC-72 (E2E is impossible without a test sink seam; unit only), PH-AC-71 (unit), PH-AC-60 and 59 (unit with fakes plus E2E for `notFound()`/`redirect()`), PH-AC-67 and 30 (need a real Server Action id: drive through a form in the browser, or read the `Next-Action` id from a fixture page).
- [important] **G5. Delivery order: step 1 cannot be verified without the E2E harness, and two spikes are missing.** Step 1 lists fault routes but not the tee/log-reader and the extra-server wiring that PH-AC-08/09/10/58/60/62/64 need. Spikes should also prove: HTTP 500 (not 200) for a page that throws before streaming under `connection()` in the root layout (PH-AC-62); `error.digest` present in the production build; Next returns 413 for an oversized Server Action (PH-AC-30, step 3).
- [minor] **G6. PH-AC-23 process test timing.** If `env.server.ts` is validated lazily, the bad value fails on first import, not at startup. Say which, and give the test a timeout.
- [minor] **G7. PH-AC-22 cold start.** The first request after start is slower (cold render); each-under-2 s over 20 requests can flake on a slow CI runner. Warm up once.
- [minor] **G8. No global "fail on CSP violation" fixture in the spec.** Round 1 proposed it (all existing E2E specs become CSP regression tests); PH-AC-31/61 do not state it. The listener must be installed before navigation (`addInitScript`).
- [minor] **G9. `gen:module` CI smoke step** (PH-AC-49) appears in section 16 but not in PH-FR-22.

## Proposals (exact wording to add)

- **G1 (section 8, replace the PH-AC-08 line):** "PH-AC-08: production build only; the fixture error message includes a per-test token taken from a query parameter, so the digest is unique per test and per attempt; exactly one log entry carries the code, asserted via the tee'd server log, polled with `expect.poll`. The token itself must be absent from the HTML, the RSC payload and the log entry (the hook never logs messages)."
- **G2 (PH-FR-23, add):** "The root-layout failure is injected by `src/app/layout.tsx` calling `assertFaultInjection()` (a function in `src/lib/fault-injection.ts`), which throws only when `DESIGN_PAGE_ENABLED` is on and the request has the header `x-fault: root-layout`; the E2E test sets that header for one navigation. With the flag off it is a no-op (covered by the PH-AC-76 unit test). If the product-manager/architect reject test code in the root layout, PH-AC-03 is component-level only and PH-AC-61 covers the global error page by rendering it at `/design/errors/global-preview` (record the loss of the real path in ADR 0015)."

Ports from `E2E_PORT` (3100): +0 main (flag on), +1 flag off, +2 telemetry-on (endpoint to the receiver), +3 closed-port destination.
