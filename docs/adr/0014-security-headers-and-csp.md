# 0014. Security headers and CSP

Status: Accepted
Date: 2026-11-13
Epic: 002-platform-hardening

## Context
The app has no security headers. Epic 003 adds browser calls to Supabase Auth and user-supplied content paths, so a Content Security Policy must be in place before then. A nonce-based CSP in Next.js has structural consequences (a proxy file, dynamic rendering), so the choice is hard to reverse once pages depend on it.

## Options considered
1. **Nonce CSP via `src/proxy.ts`** (`script-src 'self' 'nonce-<n>' 'strict-dynamic'`): strongest XSS protection; forces dynamic rendering for every page and is incompatible with PPR.
2. **Static CSP in `next.config.ts`** with `'unsafe-inline'` scripts: keeps static rendering; weak XSS protection (docs "Without Nonces").
3. **Experimental SRI hashes:** experimental, may change. Rejected.
4. No CSP: rejected.

## Decision
Option 1.
- **Mechanism:** `src/proxy.ts` (Next 16 name for middleware; Node runtime by default, the `runtime` option is not allowed there) generates a nonce per request and sets the CSP on request and response, with the matcher from the docs (skips `_next/static`, images, prefetches). The policy string is built by a pure, unit-tested function in `src/lib`; the Supabase origin comes from `publicEnv`. The root layout calls `await connection()` so every page is dynamic (confirmed needed by the spike: with the fault flag off nothing else is dynamic). The matcher excludes `api`, so `/api/*` JSON routes carry no CSP (documented limit; the static headers still apply). A small module running `z.config({ jitless: true })` is imported first in client form files so Zod's `new Function("")` probe raises no CSP violation; epic 003 client forms must import it first (convention, recorded in `docs/architecture.md`). Epic 003 adds Supabase session refresh to the same file; rate limiting would also go here.
- **Policy:** `default-src 'self'`; `script-src 'self' 'nonce-<n>' 'strict-dynamic'` (plus `'unsafe-eval'` in development only); `style-src 'self' 'unsafe-inline'` (Radix renders inline `style` attributes that nonces do not cover and Sonner injects a `<style>` at runtime; nonce-only styles are fragile for little gain; XSS protection lives in `script-src`); `img-src 'self' blob: data:`; `font-src 'self'`; `connect-src 'self' <Supabase origin>` (plus `ws:` in development for HMR); `object-src 'none'`; `base-uri 'self'`; `form-action 'self'`; `frame-ancestors 'none'`, except paths under `/design/frames/`, which get `frame-ancestors 'self'` (the `/design` showcase embeds its own pages in same-origin iframes; `/design` is dev/CI only and returns 404 in production). No `upgrade-insecure-requests`: E2E and `next start` run over plain http on localhost, and HSTS already covers production.
- **Static headers in `next.config.ts` `headers()`:** `X-Content-Type-Options: nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`; `Permissions-Policy: camera=(), microphone=(), geolocation=()`; `X-Frame-Options: DENY` (legacy, alongside `frame-ancestors`) for every path except `/design/frames/:path*`, which gets `SAMEORIGIN` (non-overlapping `source` patterns in `headers()`); `Strict-Transport-Security: max-age=63072000; includeSubDomains` in production only, no `preload`.
- **Hardening:** `poweredByHeader: false`; no CORS headers are ever set (a test asserts it); `experimental.serverActions.bodySizeLimit: '1mb'` stated explicitly (the key is under `experimental` in Next 16.4.6; the default value, so the limit is documented; an oversized body is rejected and the action does not run, the response is non-2xx (500) and the log shows `statusCode: 413`, so PH-AC-30 does not require a literal 413); `allowedOrigins` unset (Next compares `Origin` with `Host`). The body limit covers Server Actions only; route handlers that read bodies enforce their own cap.
- **Accepted limits of the policy (reviewed in PH-T-39):**
  - `strict-dynamic` semantics (CSP3): scripts inserted at run time by code that is already trusted (nonce or allowed by a trusted script) are themselves trusted, and the `'self'` allow-list is ignored in browsers that support it. So the policy blocks **parser-inserted** scripts and inline scripts or handlers **without the nonce** (the markup-injection XSS case), and does not block a script that trusted code creates and inserts. This is the intended trade for supporting Next's dynamically loaded chunks; it means a gadget in trusted JS (for example a library that builds script URLs from user input) can still be abused, so no code may build script elements or `eval`-style strings from user input. PH-AC-32 tests exactly the blocked cases.
  - `style-src 'unsafe-inline'`: CSS injection can restyle or exfiltrate attribute values through selectors; it cannot run script. Accepted, see Revisit.
  - `img-src data: blob:`: `data:` images are an exfiltration channel only if an attacker can already inject markup; needed for Next/Sonner/Radix assets and previews. Add the Supabase Storage origin to `img-src` only when a feature serves images from it.
  - `connect-src 'self' <Supabase origin>` has no `wss:` for Supabase Realtime; add it only if realtime is introduced.
  - No `frame-src`, `worker-src`, `manifest-src`, `media-src`, `child-src`: all fall back to `default-src 'self'`, which is the intent. No `report-to` yet.
  - `form-action 'self'` also blocks a plain HTML form whose response redirects to another origin (Chromium applies it to redirects). Epic 003 OAuth or magic-link flows must start from a Server Action or a route handler redirect, not from a native cross-origin form post.
  - `Permissions-Policy` lists only camera, microphone and geolocation; other features keep browser defaults. Extend the list when a feature makes a different capability sensitive (no need now).
  - HSTS is `max-age=63072000; includeSubDomains`, production only, no `preload`. `includeSubDomains` obliges every sibling subdomain of the production host to serve HTTPS: confirm this before the first production deploy. `preload` stays an explicit, separate decision.
  - A Server Action POST with **no** `Origin` header is accepted by Next (documented framework behavior). Browsers always send `Origin` on cross-site POSTs, and a non-browser client has no ambient cookie to abuse. Epic 003 must keep the session cookie `SameSite=Lax` or stricter (the Supabase SSR default) so this stays true; do not weaken it.
  - `/api/*` carries no CSP (matcher). Acceptable while the routes return JSON (`nosniff` and the static headers still apply). A route handler that returns HTML, SVG or any user-controlled markup would need its own CSP; none exists.
- **Proxy seams for epic 003 (recorded, not built):**
  - **Session refresh.** Supabase SSR's `setAll` recreates the response and rewrites request cookies. The refresh code must be composed with the CSP in one function: build the request headers with the CSP once, and every `NextResponse.next({ request })` it creates must carry those request headers and the CSP response header again, or pages lose the nonce. The matcher also excludes `/api`; if `/api` routes ever need a refreshed session, split the concerns (run refresh on a wider matcher, set the CSP only on non-`api` paths), do not drop the CSP exclusion silently. The proxy is not an authorization boundary: every Server Action and data access re-checks `getUser()`.
  - **Request id.** `onRequestError` reads only an incoming `x-request-id` or `x-vercel-id`. If the host platform sets neither, there is no id. The proxy (Node runtime, spike) can generate one and write it to the request headers; not done now because no requirement needs it.
  - **Rate limiting** would also live here (unchanged from above).
- **Fallback (recorded, not needed):** option 2, a static CSP in `next.config.ts`, stays documented as an option if E2E ever shows the nonce approach unworkable; the spike showed it is not needed (`global-error` receives the nonce).

## Consequences
- Positive: strict script policy, no inline-script XSS; Supabase Auth from the browser works because `connect-src` names its origin.
- Negative: no static rendering anywhere (accepted: the app is authenticated and mostly dynamic from epic 003); `style-src 'unsafe-inline'` remains; headers and CSP must be tested on `next build && next start`, not in dev.
- The "renders statically" line in PH-FL-03 is dropped (D15).
- **`global-error`:** it receives the nonce (spike PH-T-33), so no script-free or hash fallback is needed (PH-AC-61).
- **Spikes (done, PH-T-33):** `global-error` receives the nonce; the proxy runs on Node; static 404 and error pages are proven under the CSP by E2E (PH-T-37).
- **`/design/frames` exact-path edge (PH-T-39):** the proxy treats only paths starting with `/design/frames/` as framable, while `:path*` in the static `X-Frame-Options` source also matches `/design/frames` itself (404, no page there). That path gets `X-Frame-Options: SAMEORIGIN` and `frame-ancestors 'none'`; browsers that support CSP apply `frame-ancestors`, so it fails closed. Accepted as a note; an optional alignment is in the step 3 architect report.
- **Server Action body-limit verification:** the HTTP status is 500 and the 413 is visible only in Next's raw console output (the structured `onRequestError` entry has no status, and its digest is a hash of the message, identical for every oversized post). The E2E test therefore reads the raw line before the `digest:` line, and exactly one test may send an oversized body. Accepted: the hard assertions (non-2xx, the action returns nothing, no payload or stack in the response or log) do not depend on the raw line; only the `statusCode: 413` check does, and a Next upgrade that changes that output should fail one test loudly rather than weaken the guard.
- **Zod `jitless` convention for client code:** every client file that creates a Zod schema imports `@/lib/zod-jitless` as its first import (`live-form.tsx` is the reference). Imports are evaluated in order, so any import above it that builds a schema (`@/lib/env` does, at module load, through `publicEnv`) defeats it. A client component that imports `@/lib/env` for the browser Supabase client must therefore also import the module first. If this proves error-prone in epic 003 (a missed import shows up only as a CSP console error that the E2E violation fixture catches), the two-way-door alternative is to import `zod-jitless` once from `src/instrumentation-client.ts` (runs before hydration on every page); not adopted now because the file would add a client-bundle entry for one flag.
- **Risks:** `/api/*` has no CSP; `/design/frames/*` is the only framable path (same origin, dev/CI only); client forms must import the Zod `jitless` module first.
- Revisit: drop `'unsafe-inline'` styles if the UI stack stops needing it; add `report-to` when observability needs it.

## Spike outcome (PH-T-33, 2026-11-13)

Throwaway code (a `src/proxy.ts`, `await connection()` in the root layout, `poweredByHeader: false` and `experimental.serverActions.bodySizeLimit: '1mb'` in `next.config.ts`), reverted after the run. Next 16.4.6, Node 26.13.1, `pnpm build` then `next start --port 3300` (started and stopped by PID), driven with Playwright (Chromium) scripts and `curl`. Policy as in the Decision above. Every route builds as dynamic (`ƒ`).

**Confirmed (the Decision stands):**

1. **Nonce reaches every script.** In the HTML of `/`, every `<script>` (Next runtime chunks, `turbopack` runtime, the `noModule` polyfill, the inline bootstrap and RSC payload scripts) carries the request's nonce. Two requests to `/design` carried different nonces (PH-AC-66). In Chromium there were no `securitypolicyviolation` events on `/`, `/design`, a Link navigation (app-shell frame nav), the 404 page then its "Go to home page" Link, the 500 page and its "Try again" (router refresh), or a Sonner toast. Sanity: an inline `onclick` and a `fetch` to a foreign origin are blocked, so the policy is really enforced. Commands: `curl -si http://localhost:3300/ | grep -o '<script[^>]*>'`; Playwright script listening to `securitypolicyviolation`.
2. **`global-error` receives the nonce.** With `x-fault: root-layout` the root layout throws; the response is HTTP 500, its CSP header and its 11 `<script>` tags carry the nonce (it is server-rendered by Next from the request's CSP header), the page shows its title, styles apply and there are no violations. **Decision: no script-free or hash fallback is needed.** The `global-error` page keeps its current form (plain `<a href="/">` stays for the reason in its own comment). **The static-CSP fallback (option 2) is not needed.**
3. **The proxy runs on Node.** A response header set from the proxy reported `node v26.13.1`; it read the incoming `x-request-id` header (`curl -H 'x-request-id: abc123'` came back as `abc123`) and set response headers. Epic 003 can add session refresh to the same file.
4. **Foreign-origin Server Action is rejected.** Replaying a captured Server Action POST with `Origin: https://evil.example` (and `Origin: null`) returns 500 and the action does not run (server log: "does not match `origin` header ... Aborting the action", for fetch and for no-JS form posts). The same body with the real origin returns 200. A POST with no `Origin` header at all is accepted (documented Next behavior; browsers always send `Origin` on a cross-site POST). PH-AC-67 holds, but the status is 500, not a 4xx.
5. **UI stack under `style-src 'self' 'unsafe-inline'` and `connect-src 'self' <Supabase origin>`:** Radix inline styles, the Sonner toast and Tailwind work; a `fetch` to the Supabase origin is not blocked (only foreign origins are).
6. **Existing E2E under the throwaway CSP:** all 166 tests ran with the CSP-violation fixture active; 156 passed and 10 failed, all 10 for one reason (finding B below). After scoping `frame-ancestors` (finding B), those 10 passed (67 of 67 in the three affected spec files).

**Findings that change the plan (decided by the orchestrator on the Product Owner's delegation, 2026-11-13: A option 1, B option 1, C jitless module, D `experimental` key; applied in the Decision text, the spec (PH-FR-15/16, PH-AC-30, 61, 73, new PH-AC-79) and tasks T-34 to T-39, T-56):**

- **A. Oversized Server Action returns HTTP 500, not 413 (PH-AC-30, PH-FR-16).** `serverActions.bodySizeLimit: '1mb'` is enforced and the action never runs: a 1 MB minus 20 KB payload returned 200 and a 1 MB plus 10 KB payload was rejected. But Next reports the rejection as an internal error: the log shows `Error: Body exceeded 1mb limit.` with `statusCode: 413` in the error object while the HTTP response is **500** (fetch actions and no-JS form posts alike). The Next source has an open TODO for this (`next/dist/server/app-render/action-handler.js`: "consider checking if the error is an `ApiError` and change status code so that we can respond with a 413"). Evidence: `grep -n "413" node_modules/next/dist/server/app-render/action-handler.js`, plus the Playwright replay. Options: (1) relax PH-AC-30 to "rejected, the action does not run, response is not 2xx (500 today; Next logs 413)" and assert the log line, recommended: simplest, matches the framework; (2) enforce 413 in `src/proxy.ts` from `Content-Length` on Server Action POSTs: extra code, does not cover chunked bodies, so the framework limit stays the real guard.
- **B. `/design` embeds its own pages in same-origin iframes (`/design/frames/*`), which `frame-ancestors 'none'` and `X-Frame-Options: DENY` block** (Chromium: "Framing 'http://localhost:3100/' violates ... frame-ancestors 'none'", 112 console errors, 10 E2E tests fail because the 18 frames never load). Fix verified: the proxy sets `frame-ancestors 'self'` only for paths under `/design/frames/`, and `'none'` everywhere else. The static `X-Frame-Options` must be scoped the same way (`SAMEORIGIN` for `/design/frames/:path*`, `DENY` for the rest, with non-overlapping `source` patterns in `headers()`), otherwise the frames stay blocked in browsers that honor it. This is a literal deviation from PH-FR-15 (`frame-ancestors 'none'`) and PH-FR-16 (`X-Frame-Options: DENY`) for one non-production-facing path (the frames only exist when the `/design` flag is on). Options: (1) scoped exception for `/design/frames/*` as above, recommended; (2) `'self'` / `SAMEORIGIN` everywhere (weaker clickjacking protection on every page); (3) drop the iframes from `/design` (changes the Epic 001 showcase and tests).
- **C. Zod's JIT probe triggers a CSP violation report.** Zod 4 probes `new Function("")` (in a try/catch) when a schema is created in the browser; under a CSP without `'unsafe-eval'` Chromium reports it (`script-src eval`, a `securitypolicyviolation` plus a console error) even though the throw is swallowed and zod falls back to its non-JIT path. It happened on `/design` because `live-form.tsx` (a client component) builds a Zod schema. Zod skips the probe when `jitless` is set (`node_modules/zod/v4/core/util.js`). Verified: a small module that runs `z.config({ jitless: true })`, imported **before** any schema creation in the client bundle (first import of the client file), removes the violation. No policy change; PH-T-34 must include that module (or equivalent) and the first client form of epic 003 must import it first. Note for later: also the Zod schemas in `src/lib/env.ts` are imported by client code and run at module load, so the module must be loaded ahead of them in any client entry that builds schemas.
- **D. `serverActions` is an `experimental` key in this Next version.** `bodySizeLimit` and `allowedOrigins` must be set as `experimental.serverActions` (per the Next docs for this version); `next build` prints an "Experiments (use with caution): serverActions" notice. The setting works (finding A). Consequence: PH-T-35 and the PH-AC-73 config test must read `nextConfig.experimental.serverActions.bodySizeLimit`, and the Decision text above ("`serverActions.bodySizeLimit`") means that key.

**Other notes:**

- The proxy matcher from the Next guide excludes `api`, `_next/static`, `_next/image`, `favicon.ico` and prefetches, so JSON routes such as `/api/health` do not carry a CSP (not needed for non-HTML); the static headers in `next.config.ts` still apply to them.
- Without `await connection()` in the root layout nothing is dynamic when the fault flag is off (`assertFaultInjection()` returns before reading headers), so PH-T-34 must add `connection()` as the Decision says.
- `tests/e2e/telemetry-config-startup.spec.ts` does not use the CSP-violation fixture (it has no browser page); every other spec does.
